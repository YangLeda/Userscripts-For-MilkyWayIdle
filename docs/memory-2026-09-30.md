# 26.4.18 memory investigation — 2026-09-30

## Live-browser evidence

Ego Lite was used with the existing userscript installation and its other
enabled scripts. The isolated diagnostic game tab was disconnected by another
game window, so these are disconnected-page measurements, not a controlled
comparison of an active game with and without MWITools. No gameplay resources
were consumed and no saved settings or history were deleted.

- Initial JavaScript heap usage was about 276.9 MB. After settling and garbage
  collection it was about 120.0 MB, plus 85.4 MB reported as embedder heap usage.
  The initial peak therefore must not be presented as permanently retained memory.
- The current document contained 410 elements, while CDP counted about 78,300
  total DOM nodes. This includes detached trees and SVG resources/shadow trees;
  the difference alone does not prove that every extra node leaked.
- A heap snapshot identified a strong MWITools path:
  `featureStates → fillMarketOrderPrice scope → cleanup closure → observed list
  → detached GamePage_contentPanel`. The detached tree contained 19,637 nodes,
  including SVG shadow trees.
- Cleaning only that feature's scope in the isolated diagnostic tab reduced
  CDP node count from 78,309 to 58,491 and embedder heap usage from 86,737,008 to
  73,936,192 bytes. JavaScript heap usage fell from 115,865,316 to 114,884,628
  bytes. This establishes a real retention problem but does not explain all
  browser memory. This cleanup did not change the saved feature setting.

## Cause and fix

The market price autofill adapter returned immediately when its market list
was absent. Its old `observed` reference and MutationObserver survived until a
replacement list appeared or the entire feature was disabled. A reference to
the child list kept the removed parent interface alive.

The adapter now disconnects and clears the old observer and target whenever
the target changes, including when it becomes null. A newly mounted list still
gets exactly one observer. The existing scope cleanup remains in place.

## Additional memory contributors

The script manager held 84,763 MWITools storage keys. About 27.7 million of
34.2 million serialized characters (including key names) belonged to legacy
and per-entity XP history. These are storage-size measurements, not renderer
RSS or an estimate of recoverable RAM.

Heap inspection also confirmed persistent shared-storage caches: the full key
index, parsed entry maps, serialized read snapshots, and guild rate points.
For scale, traversing data reachable from the key array found about 12.2 MB;
from read snapshots, about 20.5 MB; and from rateCache, about 4.6 MB. These are
approximate reachable-data sizes, not exclusive retained sizes. `bases` and
`snapshots` share maps, and the key array and set share strings, so summing all
cache figures would double-count memory. The legacy migration cache was empty
in this sample. Cache eviction and persistent-history compaction were not
changed in this patch; they must preserve stale-tab merge and deletion semantics.

## Validation and limits

- Regression test: mounted modal handling, list removal, old-list mutation,
  three replacement cycles, and feature disable. Detached lists no longer
  trigger autofill; replacement lists still do.
- Native Chromium fixture through Ego: bundle the repository lifecycle adapter,
  attach a panel with 3,000 children, remove it, wait for mutation/frame work,
  then collect garbage. Before the fix, WeakRefs to the old panel/list stayed
  alive and CDP reported 3,006 nodes. With the fix both WeakRefs cleared and CDP
  reported 4 nodes, while the feature remained active.
- Actual trading, long-running active-game growth, process RSS, and attribution
  of the remaining SVG/game/other-script memory were not measured. This patch
  must not be described as eliminating every source of high memory usage.
- Raw heap snapshots and script-manager data are local diagnostic artifacts;
  they are not committed or uploaded.
