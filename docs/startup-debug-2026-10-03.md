# Mac 无法进入游戏：启动隔离与诊断（2026-10-03）

用户报告：新版启用后无法进入游戏，卸载或退回旧版可以；环境为 Mac。尚未提供受影响浏览器、脚本管理器和旧版号。此前的接口限流、公会采样修复不能作为本次问题已经解决的证据。

## 已确认的代码问题

- 原 `MessageEvent.data` getter 在返回消息前同步调用全部插件处理。用旧分发脚本与缺少字段的 `init_client_data` 夹具验证，第一次读取 `event.data` 抛出 `Cannot convert undefined or null to object`。这证明插件处理异常可影响游戏原生读取，不证明真实服务器发送了该夹具。
- 共享存储模块导入时同步迁移本站全部持久化数据，包括未进入的角色。30 个合成存储、每个 200 条记录的导入对比，旧脚本同步执行约 174 ms、136 次写入、24,506 个 GM 记录；新安全入口约 32 ms、无存储读写。这只是离线导入／绕过测试，不代表用户实际历史量或正常启动加速倍数。

## 本次处理

原始消息先返回游戏，再按顺序分批处理插件消息，每批最多四条。单条失败被记录，后续消息继续；同一事件重复读取只投递一次。不能中止仍在执行的单个无限循环或超重计算。

当前使用的存储仍按需迁移，其他历史在启动后逐个迁移，条目之间让出主线程。未使用的迁移快照释放；显式备份仍包含未访问角色的数据。没有删除用户设置、历史或迁移前副本。

启动入口在游戏模块执行前建立诊断与安全启动；安全模式完全绕过游戏／存储模块。动态导入已在单文件内打包，无额外模块请求。构建启用删除未使用声明以符合 Greasy Fork 2 MiB 限制，保留可读代码、许可证与原有功能。

## Debug 版使用

文件为 `MWITools-debug.user.js`，版本 `26.4.21-debug.2`；与正式版同名、同 namespace，作为现有脚本的替换版本安装，避免同时启用两份。移除自动更新地址以避免诊断期间被正式版覆盖。安装前保留现有脚本副本。

- 默认正常加载所有已开启功能，并显示启动诊断面板。
- 新增控制台输出（2026-10-13）：F12 打开 Console，勾选 Preserve log（保留日志），过滤 `[MWITools Debug]`，确保 Info 和 Warning 级别可见。debug 构建还逐个输出源码模块的 `module:begin`／`module:ready` 与文件名；最后一个只有 begin 而无 ready 的模块是未完成求值的线索。每个启动阶段带相对时间；失败带错误堆栈，超过 50 ms 的处理与主线程延迟带警告。每 10 秒输出当前阶段、功能状态、收到／处理／失败消息数和积压量，启动心跳持续 90 秒。
- 控制台运行 `window.__MWITOOLS_STARTUP_DEBUG__.print()`，或点面板“输出报告到控制台”，查看完整报告。`snapshot()` 返回当前报告。网络钩子报告包含原始描述符是否存在／可配置、getter 名称，以及 MWITools 安装后的 getter 是否仍在使用；被后装脚本替换时记录一次 `socket:hook-replaced`，这只是冲突线索，不能单独证明根因。
- 若 MWITools 与其他脚本同时失效，先在正常模式复现并导出，再在同一标签页点“跳过消息拦截并记录”（或地址加 `mwitoolsNoSocket=1`），观察其他脚本是否恢复并再次导出。该对照模式仍加载 MWITools 模块，但不安装核心消息 getter，依赖网络数据的功能不可用。最后可使用安全启动对照；设置和历史均保留，点“正常加载并记录”恢复。
- 主线程完全冻结期间无法输出心跳；开启 Preserve log 后，冻结前的最后阶段可帮助定位。某个阶段长时间停留不一定是错误，例如 `performance-setup:wait` 也可能是在等待玩家完成性能设置。
- 正式版也可以从脚本管理器菜单打开“MWITools 启动诊断”，点“正常加载并记录”后刷新。
- 无法进入时，在同一标签页点“安全启动（暂停插件）”。若面板也无法操作，可以在当前地址增加 `mwitoolsSafe=1`，例如 `https://www.milkywayidle.com/game?mwitoolsSafe=1`；cn 站同理。
- 安全模式只暂停本标签页的 MWITools，不影响其他脚本。点“正常加载并记录”清除本标签页的安全选择并刷新。
- 下载 `MWITools-startup-debug.json`，包含当前和上一次运行的本地日志。若标签页卡住后刷新，继续使用同一标签页以保留 sessionStorage；关闭标签页可能丢失报告。
- 记录模块加载、首次存储读取／迁移、设置、启动钩子、功能初始化、初始化消息、网络断开代码、超过 50 ms 的状态／处理器耗时，以及主线程延迟。初始化处理前保存阶段，帮助定位未返回的计算。日志最多 120 条，心跳最多运行 90 秒；无自动上传，不采集原始游戏消息、背包快照或聊天。
- 救援入口位于 userscript 正文，不能绕过脚本管理器在正文之前加载的 `@require`。若诊断面板和菜单均未出现，应检查脚本是否注入及管理器／依赖加载错误，不能据此判断游戏服务器拒绝访问。

## 实际界面验证与限制

使用 ego-browser 隔离 Space 15，在本机 Mac、Chrome 152、Tampermonkey 5.5.0 环境替换原脚本并确认保存。正式角色未启动、停止、购买、开箱或刷新任务；只是重连与诊断操作。

- 原安装版本、debug 正常启动均能进入游戏；不能复现用户的“进不去”。
- Debug 原生界面可见，角色初始化消息被记录。首次实测观察到约 2.9 秒的主线程延迟，另一轮约 1.65 秒；该数字包含游戏、插件与其他脚本的合计阻塞，不是 MWITools 单独 CPU 时间，也不能据此证明用户机器的根因。
- 安全启动后仍可进入游戏，MWITools 快捷设置未挂载；正常加载后快捷设置恢复。
- 实际点击“下载诊断报告”成功生成 schema 1 JSON，含安全模式当前记录和上次 debug 运行。日志有数量上限，较早事件可能被后续事件覆盖。
- 网络 getter 异常隔离、消息顺序、让出主线程、同事件去重、后台迁移、旧备份、日志上限、前次报告与完整分发脚本安全绕过通过回归。

仍需用户受影响环境里的诊断报告和新旧版本号来确认真实失败阶段；没有宣称 Mac 进不去、发热或整个手机无响应已经复现或根治。
