# 26.4.18 浏览器卡顿排查与修复

## 复现与原因

使用 ego-browser 的同一个隔离 Space，在实际角色页面检查。浏览器原先安装的是 26.4.17；保存仓库的 26.4.18 后，加载、页面求值及 CPU 采样停止指令出现超时。暂时绕过共享存储时页面恢复响应，因此继续检查新增存储路径。

- 共享存储每次读取都会枚举全部 GM 键、读取字段并重新拼装历史。语言缓存和本地迁移标记也被错误纳入共享数据。
- 经验历史从 IndexedDB 迁移后，全体成员共用一个 JSON 数组；公会每更新一名成员，都会重新处理整份历史。
- 每条经验样本被拆成多个 GM 键。复现过程中历史导入后，MWITools 的脚本存储达到 339,372 个键、约 94 MB 的序列化内容；浏览器实际报错 `Message exceeded maximum allowed size of 64MiB`，甚至无法注入脚本。

## 修复

- 共享存储使用批量读取、批量写入、键索引和按版本缓存的读取快照；没有变化的写入不再广播更新。远端修改及恢复备份会使相关缓存失效。
- 经验历史按稳定对象 ID 独立存储，一条样本作为一个记录，仍按时间戳合并。保留旧历史并逐对象导入；首次大公会迁移在成员之间让出事件循环。
- 语言缓存、更新清单缓存和本地迁移标记留在本地；统一备份排除这些缓存。
- 浏览器修复前已保存完整脚本存储副本到仓库外的 `mwitools-recovery/2026-09-28-tampermonkey-storage-before-perf-fix.json`。只压缩经验样本的字段表示并移除共享语言/更新缓存，保留 74,995 条样本；读回验证后，存储降至 77,660 个键、约 33 MB。完整备份未提交到 Git。

## 验证

- 单对象历史实际读取约 19 ms；126 名成员的实际经验更新合计约 241 ms。没有提交交易、生产、哞卡刷新或开箱请求。
- 完整插件恢复启用后，角色页面和库存摘要约 7.4 秒加载完成；5.8 秒 CPU 采样可正常结束，约 72% 采样为空闲，已不再长时间阻塞。该时段仍包含其他游戏辅助脚本的启动工作，不能把整体占用全部归因于 MWITools。
- 实际检查任务页、市场页及装备/库存切换，页面可响应，库存摘要重新挂载。
- 回归涵盖大历史批量读写、未变化读取不枚举全库、未变化写入不广播、远端修改、测试服隔离、备份恢复失败回滚、样本粒度、旧经验导入、按成员更新及迁移让出事件循环。
- `npm run build`、`npm run check`（577 项测试）、`git diff --check` 通过。

历史原始副本和原有本地开发配置均保留。未对其他游戏辅助脚本做代码修改或关闭其设置。
